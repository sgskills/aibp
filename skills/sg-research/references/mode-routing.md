# 模式路由合同

## 判定顺序

按用户明确意图和当前能力判定，不从“Skill 已触发”反推研究必须执行。

1. 先排除简单事实、纯摘要、翻译、润色和普通写作。
2. 在 AIBP 组合中且对应 Skill 可用时，先判相邻任务：方向/资源/年度路径给 `sg-ceo-vision`；边界不清的电商跨模块拆解给 `sg-mece`；已明确的专科单点任务给对应专业 Skill。相邻 Skill 不可用时不虚构调用。
3. 若多来源查证、比较、尽调或证据可审计的研究结论本身是主要工作，保留 `sg-research`；结论未来用于决策不自动改变路由。
4. 识别用户是否明确要“提示词、任务书、交给外部工具”。
5. 识别用户是否同时明确要报告或结论。
6. 预检当前工具能否检索并打开正文，而非仅返回摘要。
7. 按下表路由；执行中断再走部分交付。

## 路由表

| 信号 | 工具 | 路由 | 必须说明 |
|---|---|---|---|
| 要报告/查清，未要任务书 | 可用 | `research_execution` | 研究范围与截止时间 |
| 明确只要任务书 | 任意 | `research_task_pack` | 本轮是否执行过研究 |
| 要报告/查清 | 不可用 | `research_task_pack` | 工具不可用，来源未核验 |
| 同时要报告和任务书 | 可用 | `research_execution_plus_task_pack` | 报告与可复用任务包分开 |
| 同时要报告和任务书 | 不可用 | `research_task_pack` | 只交任务包，报告未执行 |
| 执行已开始但工具失败或核心证据不足 | 任意 | `research_degraded_bundle` | 已核验、缺口、未完成范围 |
| AIBP 中相邻专业任务且对应 Skill 可用 | 任意 | `non_trigger` | 点明更适合的任务类型；不执行或安装相邻 Skill |
| 简单或非研究任务 | 任意 | `non_trigger` | 简短让位 |

## 优先级解释

- 明确只要任务书时，不因工具可用而擅自执行。
- 未明确只要任务书、但同时要求报告和任务书时，工具可用则组合交付。
- 工具不可用优先于报告执行；不得用模型记忆冒充当前检索。
- “工具可用”要求至少能执行搜索、打开正文并记录定位；只见摘要不算通过预检。

## 最少追问

仅当答案会改变路由、关键结论或高风险边界时追问。否则声明合理假设并继续。例如，缺少地域会改变法律结论时追问；仅缺少排版偏好时不阻塞。

## 机读合同标识

- `[ROUTE-EXECUTION]`：工具可用且要报告时执行研究。
- `[ROUTE-TASK-PACK]`：明确要任务书或工具不可用时交任务包。
- `[ROUTE-DUAL]`：同时要两种交付且工具可用时报告加任务包。
- `[ROUTE-PARTIAL]`：执行中断或核心证据不足时交已核验发现、缺口和任务包。
- `[ROUTE-NOT-APPLICABLE]`：简单事实和非研究任务让位。
- `[ROUTE-SPECIALIST-HANDOFF]`：AIBP 中方向/资源/年度路径、边界不清的电商跨模块问题和明确专科单点任务，在对应 Skill 可用时具体让位；多来源研究本身为主要任务时不让位。
- `[TOOL-PREFLIGHT]`：执行前验证搜索、正文读取和定位能力。
