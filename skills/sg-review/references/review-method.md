# 评价分析方法

## 1. 分析顺序

按以下八步执行，不要从几条显眼差评直接跳到建议：

1. 数据盘点；
2. 去噪、分层与脱敏；
3. 高频短语提取；
4. 需求维度归因；
5. 场景识别；
6. 人群与情绪分析；
7. 隐藏商业机会与行动生成；
8. 五模块报告组装与复核。

## 2. 数据盘点

先回答：

- 输入多少条，多少条有有效正文；
- 是否有日期、星级、SKU、商品、平台和竞品字段；
- 时间跨度与商品/SKU 是否混杂；
- 是否存在空正文、重复表头、重复 ID、异常评分或对象型文本；
- 哪些模块可分析、部分可分析或不可分析。

低信息和重复文本默认保留并单列。业务决定排除时，要记录排除规则、排除前后数量和受影响编号，并对过滤后的数据重新计算全部分母。

## 3. 去噪、分层与脱敏

### 去噪

- 空白或只有符号：无效正文；
- “好评、不错、收到”等：低信息评价；
- 高度相同或模板化文本：疑似重复/模板化；
- 星级与正文明显相反：评分文本冲突。

这些是审计标记，不是对刷单或虚假交易的事实裁决。

### 分层

按可用字段覆盖星级、时间、SKU、商品/竞品和文本长短。只做抽样阅读时必须公开抽样方法和覆盖范围；要给完整主题分布时必须通读全部有效评价。

### 脱敏

先生成内部评价编号，再隐藏手机号、邮箱、证件号、详细地址、账号、订单号和会员号。报告只引用最小充分短句。

## 4. 高频短语与主题归因

### 高频短语

高频短语服务于表达和查漏，不直接等于需求。优先保留“对象 + 属性/结果”的短语，例如“表带容易断”“客服响应快”，不把“非常、挺好、收到”单独作为业务主题。

### 主题归因

V1.1 的参考维度包括：

| 一级维度 | 二级维度示例 |
|---|---|
| 外观设计 | 款式、颜值、配色、图实一致 |
| 功能性能 | 准确性、续航、防水、功能可用性 |
| 材质做工 | 材质、质感、耐用性、细节工艺 |
| 性价比 | 价格感受、价值匹配、促销预期 |
| 用户体验 | 舒适性、便捷性、适配性、学习成本 |
| 包装物流 | 包装、礼盒、物流、开箱体验 |
| 售后服务 | 客服、退换、补发、响应与解决结果 |
| 情感价值 | 满意、惊喜、礼赠、身份与情绪体验 |

这张表是起点，不是固定词典。先从当前评价建立主题边界，再合并同义表达。每个主题至少记录定义、纳入/排除条件和代表引文。

禁止只靠关键词匹配自动完成归类。含有同一个词的评价可能表达不同对象、阶段和情绪；每个命中都要回到完整句子判断。

## 5. 统计口径

### 评分

默认示例：4–5 星好评、3 星中立、1–2 星差评。用户或平台有不同口径时以已确认口径为准。

```text
评价类型占比 = 该类型有星级评价数 ÷ 有效星级评价数
```

### 主题

```text
评价覆盖率 = 提及该主题的不同评价数 ÷ 全部有效评价数
提及份额 = 该主题提及次数 ÷ 当前模块全部主题提及次数
```

同一评价可以归入多个主题；覆盖率之和可以超过 100%。同一语义事件只计一次，嵌套短语保留能说明完整对象和结果的一个片段。

部分审读时，评价覆盖率是“相对全部有效评价的已发现下界”，未审读评价不能当作没有提及。

## 6. 证据与推断

- 事实：字段或评价原文直接出现；
- 计算：按公开公式得到的数量、比例和排序；
- 推断：对需求、动机、画像、原因和价值的解释；
- 建议：计划执行的业务动作。

核心洞察原则上至少由 2 个不同评价编号支持。单条证据可以保留，但必须标为单点、低置信度，不写成稳定规律。

推断至少写一种替代解释。共现不等于因果；“可能原因”必须附验证方法。

## 7. 场景与人群

### 场景

场景需要明确的用途、时间、地点、任务或关系上下文，例如“送生日礼物”“上学佩戴”“夜间放卧室”。普通收货动作、商品属性或一个“送”字不能自动成为场景。

### 人群

分开判断：

1. 谁购买；
2. 谁使用；
3. 在什么场景；
4. 关注什么结果；
5. 为何选择或犹豫。

原文明确关系属于事实。由多条行为和动机构成的人群类型属于推断，要附证据和替代解释。年龄、收入、城市、职业等敏感或精确人口属性没有明确数据时保持未知。

## 8. 趋势、SKU 与竞品

### 趋势

只有日期可解析且窗口可比时才判断。至少披露日期覆盖率、窗口、各窗口样本数和主题口径。“近期新负面信号”还要给近期窗口、对照窗口、编号和数量。

数据稀疏、活动/商品混杂或主题未按时间编码时，只描述样本量变化或写无法判断，不推断改善、恶化和原因。

### SKU 与竞品

评价数量只能表示样本构成。排名优劣前检查商品定义、平台、版本、履约、纳入规则、时间窗口、星级/主题结果指标和样本失衡。

任一关键口径未知时，展示分组事实并写“当前无法判断最好或最差”。如果要排除记录、合并 SKU 或改变窗口，先展示新口径和影响，再取得用户确认。

## 9. 隐藏商业机会发现

完整报告必须执行本步骤并输出至少一条机会。依次检查：

1. 重复出现但没有稳定解决的结果；
2. 用户主动提出的愿望、替代方案或权宜办法；
3. 场景、人群或规格之间的错配；
4. 同一体验的正负分化；
5. 正向惊喜是否尚未被页面、内容、产品或服务承接；
6. 产品承诺、交付、使用和售后之间的连续摩擦；
7. 评价全部低信息时，是否存在评价采集和决策资产机会。

机会需要回答：

```text
谁 + 在什么情境 + 想完成什么结果
现有产品/表达/服务为什么没有充分满足
可以尝试的新价值、规格、选择机制、内容或服务是什么
哪些评价支持，哪些证据反对，当前最关键未知是什么
用什么小实验验证，何时继续，何时停止
```

### 机会与整改的区别

- “包装破损，换供应商”是问题和整改；
- “送礼用户需要可预期的礼盒完好与到达状态，测试礼赠保障组合”才是机会假设。

机会可以关联整改，但必须说明新增或重组了什么价值。

### 证据降级

- 2 条以上独立评价：多评价信号，仍是探索性假设；
- 1 条：单点信号、低置信度、探索性假设；
- 只有低信息评价：只能输出评价资产机会；
- 零条有效评价：不能声称完成报告，先补数。

单个商品买后评价通常只能支持当前样本中的机会假设。市场空白、市场规模、付费意愿、转化和利润还需要竞品、搜索、价格、未购买者、订单或实验数据。

## 10. 行动生成

行动按严重度、证据强度、影响范围、可逆性、验证成本和执行依赖排序。

每条行动写：

- P0/P1/P2 优先级；
- 产品、视觉/Listing、渠道或服务类型；
- 关联需求、风险或机会；
- 具体动作与责任对象；
- 主指标和可计数分母；
- 观察周期、判定规则和停止/复核条件；
- 执行难度。

没有订单、妥投、曝光、触达、成本或效果分母时，不把评价提及数称为发生率、转化率或 ROI。

## 11. 报告复核

交付前逐项核对：

1. 五模块与综合结论顺序完整；
2. 数据不足模块没有被删除或补造；
3. 数字、公式、编号和短引文相互一致；
4. 人群、趋势、比较、因果和 ROI 没有越界；
5. 正向亮点写了商业价值或动作；
6. 负向问题写了原因假设和验证；
7. 隐藏商业机会真实存在、证据强弱可见且不只是整改；
8. P0/P1/P2 行动可执行、可验证、可停止；
9. 局限性和补数项与当前数据相符。

脚本绿灯只能证明可机械检查的下界，不能替代阅读原始评价和最终报告。
