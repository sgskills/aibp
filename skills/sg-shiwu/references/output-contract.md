# 输出合同

## 标准交付顺序

必须依次输出以下七段；段落可以简短，但不得换序、合并或用空白模板伪装完成。

### 1. 输入质量审计与图片编号

逐图列出 `IMG-nn`、可读性、实拍/渲染/未知、清晰度、覆盖/遮挡、色彩与尺度可靠性、关键成像风险。不可读图片也要编号并说明原因。

### 2. 产品/变体/配件/包装/道具分组

列出组 ID、类型、包含的 IMG、合并或拆分依据和分组置信度。临时组和“是否同一 SKU”冲突必须显式可见。

### 3. 视觉指纹证据表

按产品与变体分表。每行固定列为：

| 特征字段 | 值 | IMG 与局部位置 | 证据类型 | 稳定性 | 复刻优先级 | 置信度 | 理由 |
|---|---|---|---|---|---|---|---|

证据类型、稳定性、优先级和置信度只能使用 [证据政策](evidence-policy.md) 定义的枚举。用户确认但无图片位置时，在证据列明确写“用户文字确认，无图像位置”。

### 4. 工具中立的固定身份锚点

先写共享身份不变量，再按变体写差异片段。只吸收获支持的 P0/P1 身份不变量或变体特征；语言为自然中文，不包含工具名、模型参数、场景词、未解决冲突或还原承诺。

### 5. 场景变量

列出视角、状态、背景、灯光、阴影、景深、倒影、道具等当前图像条件，并注明“可替换”“需固定”或“拍摄伪影”。不把它们混进身份锚点。

### 6. 负面约束与易漂移点

逐条对应当前证据中的风险，说明“不得改变/混入/补写”的具体对象，例如变体串色、配件并体、透明体染背景色、Logo 乱补、局部数量漂移。避免通用形容词堆砌。

### 7. 未知、冲突和最小补拍清单

分别列出：仍不可判断的字段；相互冲突的来源和值；为解决每一项所需的最少图片（对象、角度/局部、光线、尺度或状态）。没有对应事项时明确写“无”，不得补造问题。

## 降级输出

只有 URL 且不可合法读取，或根本没有图片时，不生成七段空报告。只输出：

1. 无法分析的原因；
2. 未做出的结论；
3. 最小上传清单。

这属于输入降级，不等于完成视觉提取。

三个标题和三个有实质内容的正文缺一不可；不得复用七段标题，也不得以“待补充”等占位文本通过。

## 纠错输出

沿用七段顺序，但只在相关段落列出变化；证据表只给受影响行，身份锚点只给受影响片段，其余段落标记“无变化”。末尾追加“变更摘要”，记录组/变体、字段、原值、新值、来源、证据类型、受影响输出和本轮未解决项。不得全量重写或把某一变体的更正传播给其他变体。

## 机器可验收伴随数据

正式交付应同时保留与实际 Markdown 一一绑定的结构化伴随数据，至少包含 `route`、`groups`、`features`、`identity_anchors`、`history` 和 `rule_version`。运行 `python -B scripts/output_guard.py REPORT.json SOURCES.json` 校验完整报告；增量更新再提供旧状态与事件文件。校验失败即不得把该输出作为合格交付。

来源登记表覆盖本轮全部图片、用户陈述、引用资料与不可信载荷，而不只是被特征引用的子集。每项只含 `id`、`kind`、`readable`、`active`、`group_ids`：`kind` 取 `image/user/reference/untrusted`，可读性和当前有效性使用布尔值，`group_ids` 显式声明来源属于哪些实体组。特征伴随数据须增加 `group_id`，让来源、字段和锚点的实体归属可以机械核对；图片路径、哈希和许可放在运行清单，不伪装成视觉证据。

分组 ID 使用 `P01`、`P01-V01`、`ACC`、`PACK`、`PROP`、`UNK` 族；变体必须指向已存在的父产品。边界停止只说明本 Skill 未执行该任务，`handoff_target` 默认为空，不得声称已自动转交一个未经当前环境核实的工具。
