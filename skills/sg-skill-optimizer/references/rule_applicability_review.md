# 规则适用性复核

静态检查只提供候选问题，不能代替对目标 Skill 用途的理解。开始给分前，先判断每条规则是否真正适用。

## 先识别目标类型

- **元 Skill**：诊断、优化、创建、路由或管理其他 Skill 的工具。
- **业务 Skill**：完成具体业务任务的工具，例如报表分析、写作、设计或代码交付。
- **混合 Skill**：既有业务交付，也有可复用的管理或评测流程。

## 适用规则

- 所有 Skill 都检查：frontmatter、输入输出边界、安全、真实失败分支、资源引用和未授权写入。
- 只有元 Skill 才检查：是否强制交付完整 Skill 体检报告、是否有优化计划与确认门。
- 业务 Skill 可以使用 HTML、Markdown、表格、文件或其他适合业务的交付；不得因为缺少“诊断报告模板”而自动判为失败。
- 有编号步骤、引用的输出契约或任意安全模板时，应先识别其实际作用，再决定是否属于缺失。

## 报告写法

对每一个可能误判的自动检查，写明：

1. 规则是否适用：`适用`、`不适用` 或 `需要人工复核`；
2. 证据：目标 Skill 的具体段落、资源或行为；
3. 处理：保留问题、改为 `N/A`，或说明为什么不能仅凭关键词下结论。

禁止为了让总分好看而取消真实缺陷；也禁止因为通用清单包含某项就给不相关的业务 Skill 扣分。
