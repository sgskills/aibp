# 偏好档案

偏好适配是执行时选择写法，不是 Skill 自改代码。不得把某位用户的偏好写回 `SKILL.md` 或默认平台规则。

## 最小结构

```json
{
  "profile_id": "stable-user-chosen-id",
  "scope": {"platform": "tmall", "store": "店铺标识", "category": "类目标识"},
  "source": "用户明确说法或纠正的原文摘要",
  "confirmed_at": "2026-08-10T10:00:00+08:00",
  "version": "1.0",
  "status": "active",
  "preferences": {"space_policy": "forbid", "style": "保留完整词组"}
}
```

所有档案必须有 `profile_id / scope / source / confirmed_at / version`。作用域字段缺失不等于通配；确需通配时显式写 `*`。不同 profile 不合并、不猜继承，也不按相似店铺名串用。用户已提供的标量值保留原值与原类型，例如 `version: 1` 不改成 `"1"`；用户说“抖店”时，可见偏好卡仍写“抖店”，内部调用所需的 `douyin` 只留在校验输入。不为解释同一偏好新增同义字段，例如已有 `space_policy: "allow"` 时不再增加重复的 `style`。

## 学习与覆盖

- 只学习用户明确要求或明确纠正；“这次看起来喜欢”不构成偏好。
- 本次纠正立即在当前任务生效。
- 用户本次明确要求优先于旧软偏好；真实性、合规和平台 `hard` 规则不可被偏好覆盖。
- 不收集姓名、电话、账号、地址、订单、支付信息等个人敏感信息。店铺/类目作用域用最小必要标识。

## 跨会话

只有用户明确说“记住/保存为偏好”才可以尝试跨会话保存。当前 Runtime 没有获准存储能力时，输出一张可复制“偏好卡”，写明尚未永久保存；不得声称“已经记住”。

## 查看、撤销与恢复默认

- 查看：列出 profile_id、作用域、来源、确认时间、版本、状态和偏好，不显示无关信息。
- 撤销：把选定版本标为 `revoked`，不删除审计信息；后续不得激活。
- 恢复默认：当前请求不激活任何个人 profile，使用平台硬规则和通用方法；不自动删除历史档案。

调用校验器时必须显式传入 `active_profile_id`。未传、找不到、已撤销或作用域不匹配时，返回未激活状态并保持隔离。
