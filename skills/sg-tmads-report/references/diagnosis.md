# 诊断方法

## 先写证据等级

每条结论标为以下之一：

- **数据事实**：由当前数据岛的原始值或公式直接得到。
- **结构性推断**：由多个数据事实推导，写清替代解释。
- **情景估算**：依赖全店统一毛利率、退款金额率或其他用户假设。
- **待核验**：需要后台口径、归因窗口、商品结构或官方来源确认。

归因报表不是增量实验。即使归因窗口已知，也不要把相关性或归因记账写成真实因果增量。

确定性脚本只生成证据模型，不自行补写经营诊断或动作。Agent 必须在审表、追问和计算后，把执行摘要、诊断与行动整理成结构化叙事，再与证据合并为同一个 `ReportModel v2.1`。任何叙事都要引用模型中的数据岛、对象、字段、指标、公式或用户约束。

## 分层诊断

### 1. 数据可用性

先回答：这份数据能否支持用户目标？列出能力等级、最大风险、缺失字段和未合并数据岛。

### 2. 整体周期

展示规模与效率的总分子、总分母和周期比率。若有多个不兼容数据岛，分别展示，不给伪“全店总计”。

### 3. 每日趋势

按日期汇总原始分子分母，再计算当日比率。关注变化点，但不自动给异常阈值；日期缺口不补 0。

### 4. 计划周期

按计划 ID 汇总，并保留计划名。建议使用可解释的组合，而非单一 ROI 排名：

- 有规模且商品毛利口径贡献为正；
- 有成交价值但成本接近或高于保本；
- 有花费但缺少转化证据；
- 数据量不足，暂不能判断。

不要发明“高/低”的通用阈值。比较基准按优先顺序使用：用户经营目标、保本公式、同店历史、同一周期内可比计划。样本量少时直接写“不足以判断”。

### 5. 商品与计划组合

仅在同时有商品身份和计划身份时分析。全店统一毛利率/退款率套多商品的结果都标“情景估算”，不能据此宣布某商品真实盈利。

若全店统一费率跨多个日期使用，即使只有一个商品，推广贡献盈亏和保本 PPC 仍标为情景估算；不要把该标签扩散到 ROI、CPC 等基础事实。

### 6. 动作建议：目标方向与当前许可分开

每条动作先回答两个不同问题：

1. 如果证据继续成立，最终想做什么（`target_action`）；
2. 按当前证据，现在安全允许做什么（`allowed_action`）。

每条动作写成：

```text
对象 → 目标动作 → 当前允许动作 → 证据 → 门禁/约束 → 变化幅度来源 → 复核合同
```

预算增减、出价增减、暂停、关闭或继续投放必须考虑用户提供的经营目标、预算、控制杠杆和不可暂停约束。用户未提供时写为待确认，不自行生成百分比、金额或固定观察天数。

动作不要退化成一张 ROI 排名表：

- **增加预算**：需要规模目标、预算空间/资金来源和预算受限证据；仅有盈利不够。
- **减少预算**：需要用户目标或保本/同店可比基准、归因成熟与完整日期；没有通用 ROI 阈值。
- **增加出价**：需要确认出价可控、放量目标、可解释的流量机会与实验停止条件；CPC 不是出价。
- **降低出价**：需要确认出价可控、效率压力及可比基准；不能只因 CPC 数字较高。
- **暂停**：可恢复，写明恢复条件。
- **关闭**：比暂停更不可逆；除成熟证据和无保护约束外，还要用户明确确认。未达门禁时可以是目标候选，但当前只允许核验。
- **保持并观察**：不是“没有建议”，要写清维持条件与何时升级/降级。

### 7. 逐计划决策矩阵

对每个可识别的计划 ID 生成一条独立 `ActionRecord`，不得把多个计划 ID 合成一句建议。Top 卡片只负责优先级，完整行动队列必须覆盖全部计划；证据不足的计划也要明确记录 `target_action=request_data|investigate`，不能静默遗漏。

每个计划按同一顺序审查五个维度，不使用自创分数或行业阈值：

1. **证据成熟度**：日期完整、异常行处理、归因状态、对象身份和可比周期；
2. **经营目标匹配**：用户要放量、控亏、清库存还是守预算；目标未知时不得默认放量；
3. **经济与效率证据**：优先使用用户目标、商品毛利口径保本线、同店历史或同岛可比计划；缺毛利/退款时不冒充盈亏判断；
4. **控制杠杆是否真实存在**：预算受限证据、资金来源、出价可控确认、不可暂停/保护约束；
5. **动作可逆性与复核合同**：先选择最小可逆动作，写清升级、停止、恢复和复核触发条件。

用下列逻辑区分相近动作：

| 候选方向 | 必要证据 | 当前缺口存在时 |
|---|---|---|
| 增加预算 | 放量目标 + 经济/目标门禁通过 + 确认受预算限制 + 预算空间或资金来源 | `investigate` 预算限制与资金来源 |
| 增加出价 | 放量目标 + 计划级出价可控 + 可解释的流量机会 + 归因成熟 + 停止条件 | `investigate` 控制杠杆，不能把 CPC 当出价 |
| 降低出价 | 效率压力 + 计划级出价可控 + 用户/同店可比基准 + 可回滚实验 | `investigate` 出价模式与基准 |
| 减少预算 | 用户要控制风险暴露 + 归因与日期完整 + 有目标/保本/同店证据 | `investigate`，不得用通用 ROI 阈值 |
| 暂停 | 成熟证据支持停止暴露 + 无保护约束 + 恢复条件 | 仅列暂停候选，当前先核验 |
| 关闭 | 暂停门禁全部通过 + 用户明确关闭确认 + 更长周期或既有暂停实验仍支持 | `target_action=close`，`allowed_action=investigate` |
| 保持 | 当前证据不支持更安全的改变，或表现符合用户目标 | 写明维持与升级/降级条件 |

同一计划可能同时出现“效率好但没有预算受限证据”“效率差但归因未成熟”等冲突。不要强行选直接动作：保留目标方向，把当前允许动作降级为核验，并把冲突写进 `constraints`。

结构化诊断至少包含：`claim_type / object_type / dataset_id / object_id / evidence_refs / finding / alternative`。结构化行动至少包含：`target_action / allowed_action / action_code / action_level / object_type / dataset_id / object_id / evidence_refs / preconditions / constraints / review_metrics / review_trigger`；目标与当前动作不同时填 `upgrade_conditions`，控制实验填 `stop_conditions`，暂停填 `resume_conditions`，出价动作填可解析的 `control_ref`，关闭动作填可解析的 `confirmation_ref`，预算迁移填 `funding_source_ref / funding_target_ref`。

`evidence_refs` 必须能解析到同一个报告模型中的对象和指标，且与行动对象一致。以下任一情况都属于阻断错误：缺证据、引用不存在或错对象；目标数据岛没有对应维度；未知/冲突归因下直接把零成交升级为暂停；受保护计划被暂停；硬预算上限下无资金来源地增加总预算；肯定式因果主张。阻断时不展示该叙事，`report_status` 保持 `evidence_only`，HTML 只能叫“数据分析附件”。

不要用简单禁词误杀边界说明。“广告带来新增成交”是因果主张；“不能证明广告带来新增成交，归因不等于因果”是合规边界。归因窗口已知最多支持 `claim_type=attributed` 的“报表归因成交”，永远不自动支持 `causal`。

## 杂乱或错误报表

- 表头错位：先定位候选表头，展示映射台账后计算。
- 多 Sheet：分别盘点，空白/说明页不丢失审计记录；不同数据岛不乱加。
- 错误报表：描述已有内容指标，明确不能支持的推广结论，并给出下一次导出所需字段。
- 混合归因：分别展示花费和归因成交，提示可能重叠，不计算跨岛 ROI。
- 大表：先整体，再每日，再计划，再完整明细；不得只展示 Top N 后丢弃其余计划。

## 补数清单模板

按实际缺口裁剪，避免一次索要所有字段：

- 日期；
- 计划 ID 与计划名称；
- 展现量、点击量、花费；
- 总成交笔数和/或成交人数；
- 总成交金额；
- 商品 ID/名称（需要商品诊断时）；
- 报表来源、数据粒度、归因窗口；
- 商品毛利率及口径、退款金额率及周期；
- 预算与不可暂停约束。
