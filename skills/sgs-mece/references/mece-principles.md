# MECE 结构化拆解原则

> 本文件是 sgs-mece 的方法参考，用于检查同层分支是否重叠、遗漏或混用标准。

## 历史来源与项目声明

根据 McKinsey 对 Barbara Minto 的访谈，MECE 由 Minto 在任职期间形成、命名并推广。参见：[Barbara Minto: “MECE: I invented it, so I get to say how to pronounce it”](https://www.mckinsey.com/alumni/news-and-events/global-news/alumni-news/barbara-minto-mece-i-invented-it-so-i-get-to-say-how-to-pronounce-it)。

本项目独立采用 MECE 作为通用结构化原则，与 McKinsey 无隶属、合作或背书关系。

---

## 一、什么是 MECE

MECE 是四个英文单词的首字母缩写：

| 字母 | 英文 | 中文 | 含义 |
|------|------|------|------|
| **M** | Mutually | 相互地 | — |
| **E** | Exclusive | 独立的、互斥的 | 分类之间不重叠 |
| **C** | Collectively | 集体地、共同地 | — |
| **E** | Exhaustive | 穷尽的、无遗漏的 | 分类加起来覆盖全部 |

**一句话定义：** 对问题进行分类时，每一类之间互不重叠，所有类别加起来刚好覆盖全部情况，没有遗漏。

## 二、MECE 的四种切分方法

### 方法一：二分法（是/否）

把问题切成两个互斥的部分。

| 切分维度 | A 类 | B 类 |
|---------|------|------|
| 内外 | 内部因素 | 外部因素 |
| 盈亏 | 收入端 | 成本端 |
| 时间 | 过去 | 未来 |
| 可控性 | 可控 | 不可控 |
| 相关性 | 相关 | 不相关 |

**例子：** 分析公司业绩下滑
```
业绩下滑原因
├── 内部因素（可控）
│   ├── 产品问题
│   ├── 运营问题
│   └── 团队问题
└── 外部因素（不可控）
    ├── 市场环境
    ├── 竞争对手
    └── 政策法规
```

### 方法二：过程法（按流程/步骤切分）

按照事物发展的时间顺序或流程步骤来切分。

**例子：** 电商转化漏斗
```
用户购买路径
├── 曝光（多少人看到了）
├── 点击（多少人点进来了）
├── 浏览（多少人看了详情）
├── 加购（多少人加购物车了）
├── 下单（多少人提交订单了）
├── 付款（多少人真的付钱了）
└── 复购（多少人再次购买了）
```

每一层都是独立的步骤，合起来覆盖了完整的购买路径。

### 方法三：要素法（按构成要素切分）

把一个整体拆成构成它的各个部分。

**例子：** 利润构成
```
利润 = 收入 - 成本

收入 = 流量 × 转化率 × 客单价 × 复购频次
成本 = 获客成本 + 产品成本 + 运营成本 + 售后成本
```

### 方法四：矩阵法（两个维度交叉）

用两个独立的维度交叉，形成四象限或九宫格。

**例子：** 用户分层
```
          高活跃    低活跃
       ┌────────┬────────┐
高价值 │ 核心用户│ 沉睡用户│
       ├────────┼────────┤
低价值 │ 潜力用户│ 流失用户│
       └────────┴────────┘
```

## 三、MECE 的常见错误

### 错误 1：分类重叠（不 Mutually Exclusive）

❌ **错误示例：**
```
用户分为：新客户、老客户、大客户、VIP客户
```
问题："大客户"和"老客户"可能重叠，一个人可以既是老客户又是大客户。

✅ **正确做法：**
```
用户分为：
- 按消费金额：高价值 / 低价值
- 按活跃程度：高活跃 / 低活跃
- 两个维度交叉 → 四象限
```

### 错误 2：遗漏情况（不 Collectively Exhaustive）

❌ **错误示例：**
```
流量来源：抖音、小红书
```
问题：漏了淘宝、微信、自然搜索、付费广告等。

✅ **正确做法：**
```
流量来源：
- 自然流量（搜索/推荐/内容）
- 付费流量（站内/站外）
- 私域流量（微信/会员）
- 外部流量（合作/导流）
```

### 错误 3：层级混乱

❌ **错误示例：**
```
提升利润的方法：
1. 降低获客成本
2. 提升客单价
3. 优化产品包装
4. 减少退货
```
问题："优化产品包装"和前面的不在同一层级。降低获客成本是策略，优化包装是具体动作。

✅ **正确做法：**
```
提升利润
├── 增加收入
│   ├── 提升流量
│   ├── 提升转化率
│   ├── 提升客单价
│   └── 提升复购率
└── 降低成本
    ├── 降低获客成本
    ├── 降低产品成本
    ├── 降低运营成本
    └── 降低售后成本
```

### 错误 4：切分标准不统一

❌ **错误示例：**
```
产品问题：质量问题、价格问题、物流问题、客服问题
```
问题："价格问题"是产品属性，"客服问题"是服务环节，不在同一维度。

✅ **正确做法：**
```
先确定维度：
- 维度一：产品属性（功能/外观/质量/价格）
- 维度二：服务环节（售前/售中/售后）
- 分别切分，不混用
```

## 四、MECE 的实操原则

### 原则 1：先定义边界，再开始切分

切分之前，先明确：
- 我要分析的问题是什么？
- 问题的边界在哪里？
- 我要解决到多细的粒度？

### 原则 2：每一层只用一种切分标准

同一层级，必须用同一个标准切分。

```
❌ 混用标准：
电商问题
├── 流量问题（按环节）
├── 价格问题（按要素）
└── 客服问题（按部门）

✅ 统一标准：
电商问题
├── 收入端问题（按利润公式）
│   ├── 流量不足
│   ├── 转化率低
│   ├── 客单价低
│   └── 复购率低
└── 成本端问题（按利润公式）
    ├── 获客成本高
    ├── 产品成本高
    ├── 运营成本高
    └── 售后成本高
```

### 原则 3：拆到能执行为止

不要停在抽象层。

```
❌ 太抽象：
└── 提升转化率

✅ 能执行：
└── 提升转化率
    └── 详情页优化
        └── 首屏增加用户证言视频
            └── 收集10个真实用户视频 → 剪辑成15秒 → 替换当前首屏主图
```

### 原则 4：验证 MECE

每次拆完，问自己两个问题：
1. **有没有重叠？** —— 如果有，调整分类标准
2. **有没有遗漏？** —— 如果有，补充维度

## 五、MECE 与电商的结合

MECE 在电商中最有价值的三个场景：

### 场景 1：问题定位

当业务数据异常时，用 MECE 快速定位根因。

```
销售额下降
├── 流量下降
│   ├── 自然流量下降
│   ├── 付费流量下降
│   └── 私域流量下降
├── 转化率下降
│   ├── 点击率下降
│   ├── 加购率下降
│   └── 付款率下降
└── 客单价下降
    ├── 用户买便宜的多了
    ├── 关联销售少了
    └── 促销活动拉低均价
```

### 场景 2：策略制定

制定增长策略时，用 MECE 确保没有遗漏增长杠杆。

```
增长策略
├── 现有用户价值最大化
│   ├── 提升复购频次
│   ├── 提升客单价
│   └── 降低流失率
├── 新用户获取
│   ├── 提升自然流量
│   ├── 优化付费投放
│   └── 拓展新渠道
└── 运营效率提升
    ├── 自动化工具替代人工
    ├── 流程标准化
    └── 减少损耗/退货
```

### 场景 3：资源分配

预算有限时，可先按决策阶段建立候选预算桶，再用业务目标、渠道数据和实验结果确定分配。

```
营销预算分配
├── 品牌认知（让不知道的人知道）
├── 兴趣激发（让知道的人感兴趣）
├── 转化成交（让感兴趣的人买）
└── 复购留存（让买过的人再买）
```

以上仅是分类示例，不提供通用比例。实际预算必须写明目标、归因口径、验证周期和继续/停止条件。

## 六、一句话总结

> **MECE 不是让你想更多，而是让你想更清楚。**
>
> 它的价值不在于拆解本身，而在于拆解过程中逼你直面问题的全貌，不逃避、不遗漏、不重复。
